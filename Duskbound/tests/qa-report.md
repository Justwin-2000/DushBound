## 输入机器人实战

机器人从未经改写的 `newState()` 开始，步行接近 NPC 并调用 `interact()`，只在实际出现的对话中选择选项。训练通过三连、两次闪避和格伦定时落下的木剑完成，不注入训练命中事件。

战斗只发送摇杆方向与 `attack()`、`dodge()`、`block()`、`potion()`。没有修改玩家/敌人生命、位置、体力、冷却、物资或任务阶段，也没有直接调用伤害、清房、胜利或结局函数。

机器人可读取精确预警时间，因此这一证据证明引擎流程可达性，不代表真人反应能力、触控体验或真机性能。所有时间均为**加速执行的模拟游戏时间**。

| 场景 | 实际结果 |
| --- | --- |
| 精准防守策略，3 种种子 × 30/60 Hz | 6/6 通关；包含两个结局；163.70～176.80 秒 |
| 只进攻与喝药，3 种种子 × 30/60 Hz | 6/6 抵达首领后死亡；正常死亡回城 |
| 100 种种子，30/60 Hz 交替 | 100/100 通关；累计模拟 16,604.68 秒；无超时 |
| 同一局连续 10 次完整远征 | 10/10 完成；累计模拟 1,750.97 秒；0 次死亡 |
| 首次盲攻死亡，回镇后切换防守策略再挑战 | 死亡 1 次，随后正常通关；无阶段修改 |

十次连续远征中，首领共召回 10 次，六种招式均出现；观测到同时存在敌人最多 3、投射物最多 1、瞬态效果最多 10。保存事件均通过字段校验。此结果仅说明这些被执行路径中的对象数有界，并不等同于堆内存泄漏检查。

复现命令：

```powershell
node tests/bot-playthrough.mjs
node tests/bot-soak.mjs
```

两者向标准输出写入 JSON 结果；第二个命令执行 100 种种子、10 次重复远征以及死亡后再挑战，若预期失败则返回非零退出码。

## 已发现并回归通过的问题

1. 敌人 `history`、攻击坐标等缺失或异常时原先能通过保存校验，可能导致首领恢复后崩溃。已补全校验，相关测试通过。
2. 首领两次完美格挡之间挨打原先没有重置连续计数。已修正并回归。
3. 双冲锋第一击被第二次完美格挡打断时，后续冲锋原先会覆盖眩晕状态。已修正并回归。

本轮输入实战未新增阻断通关或重复远征的缺陷。

## 尚不能据此确认

- 真人首次游玩的时长、实际触控与多点输入、刘海安全区、浏览器渲染、Android 安装与后台切换。
- 30～45 分钟的设计体验目标。机器人跳过阅读并精确反应，不能直接推导真人时长；目前可执行流程较短，需要真人游玩评估，不能将目标时长写成已验证结果。
- 首领对新玩家的难度。盲攻策略全部失败，说明防守非常重要，但这不直接证明难度不合理。
- 真机 60 FPS、长期堆内存变化、音频设备行为。

上述 UI、设备与真人项目应由对应实际测试报告提供独立证据。
