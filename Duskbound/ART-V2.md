# 美术 v2 路线图：从程序方块到高审美

> 目标：把当前"程序绘制的方块"逐步替换为有统一审美标准的美术资产，**逻辑层完全不动**。
> 前提：碰撞半径、攻击生效时点、判定窗口都独立于贴图（README 已声明），换美术不应改变手感。

---

## 一、先说清现状：为什么现在"提不上去"

`web/src/renderer.js` 里所有角色、建筑、地面都是用 `fillRect` / `poly` 画的**轴对齐方块**，逻辑分辨率 960×540。这个画法决定了天花板：

- 没有斜线（`rect` 只能画正矩形），所以屋顶、山脊、衣褶全靠三角 `poly` 硬凑
- 没有 1px 级别的细节与轮廓光，角色在浅色墙面前会"糊"进背景
- 颜色是散落的字面量（`#674d54`、`#5a645e`…），没有受限色板，所以整体偏脏
- 每加一个细节都要改渲染代码，**美术产能被代码卡死**

所以 v2 不是"在现有基础上加细节"，而是**换渲染架构**。这也是为什么它必须分阶段。

## 二、四个阶段（按收益/成本排序）

### 阶段 0 · 资源管线（一次性，必须先做）

| 项 | 内容 |
|---|---|
| 目录 | `web/assets/sprites/`（单帧 PNG/WebP）+ `web/assets/atlas.json`（帧清单） |
| 工具 | `tools/build-atlas.mjs`：把图集切成帧、生成清单、校验尺寸 |
| 渲染 | 渲染层抽出 `drawSprite(name,x,y,facing,frame)`，与现有 `human()/enemy()` 并存，可逐项开关 |
| 关键 | **保留现有程序绘制作为降级路径**，素材缺失时不崩、不影响判定 |

做完这一步，之后换美术只改素材文件，不动代码。

### 阶段 1 · 角色（收益最高，先做）

- 玩家：待机 / 跑动 / 三段攻击 / 闪避 / 格挡 / 完美格挡 / 受击 / 倒地 / 起身 / 死亡 / 饮药
- 4 名 NPC：待机 2 帧 + 交谈 1 帧
- 尺寸：48×64 或 64×64，统一整数倍放大
- **换完这一层，游戏的"廉价感"会消失大半** —— 因为玩家 90% 的时间在看自己的角色

### 阶段 2 · 敌人与首领

- 3 种普通敌人 + 蚀化精英 + 失灯守卫（六种招式 + 转阶段 + 眩晕，帧数需求最大）
- 每个攻击必须有**可读的预备动作**（规格书 §9.4 要求"不能只依赖颜色"），这是像素动画里最吃功力的一环

### 阶段 3 · 场景

- 每个区域一张 2240×540 预渲染背景板，替代现在程序画的建筑/树/地面
- 前景层（草丛、栅栏）单独一张带透明通道，做视差
- 灯火用加法混合的光照层，而不是现在的 `radialGradient` 光晕精灵

### 阶段 4 · 特效与 UI

- 攻击轨迹、命中火花、死亡消散改为帧动画
- UI 图标现在已经是不错的 SVG 线条，只需统一线宽与圆角

## 三、"极高审美"怎么落地成可验收的标准

审美不能只靠感觉，要能验收。定这五条硬标准：

1. **受限色板**：全套素材收敛到 32–48 色，落成 `web/assets/palette.json`，代码里禁止再出现裸色值
2. **统一光源**：约定光从右上、色温偏暖 → 所有阴影统一偏冷、统一方向。现在屋顶高光和地面阴影方向是不一致的
3. **轮廓可读性**：角色边缘加 1px 亮边/暗边，保证在任意背景上都能一眼分清（现在浅色墙面前会糊）
4. **像素密度一致**：所有素材同一像素尺寸，禁止不同分辨率混用；缩放只允许整数倍
5. **动作品质**：每个动作至少 4 帧，攻击必须有预备 → 命中 → 收招三段可辨

每阶段产出一张 before/after 对照截图，存 `tests/output/art-v2-*.png`，作为验收凭证。

---

## 四、没有专职美术怎么办

现实路径是"生成 → 降色 → 人工修边"：

1. AI 生成单帧或动作参考图（像现在的 `title.webp`/`world.webp`）
2. 降色到受限色板、像素化到目标尺寸
3. **人工修轮廓与光照**——这一步不能省，也是"审美"和"AI 味"的分界线
4. 无损原图统一放 `art-source/`，不进 APK

现成的 `tools/png-to-webp.mjs` 已经能处理第 2 步的编码环节；缺的是降色与对齐工具（阶段 0 一起做）。

## 五、建议的执行顺序

| 顺序 | 内容 | 产出 |
|---|---|---|
| 1 | 阶段 0 管线 + 用**玩家**做试点 | 管线跑通 + 玩家新形象对照图 |
| 2 | 阶段 1 其余角色 | 全部人类角色替换完毕 |
| 3 | 阶段 2 敌人与首领 | 战斗可读性达标 |
| 4 | 阶段 3 场景 | 整体观感跃升 |
| 5 | 阶段 4 特效与 UI | 收尾统一 |

**这是目前剩余工作量最大的一块**，瓶颈在素材产能而不是代码。代码侧（阶段 0 的管线 + 渲染层 sprite 分支）大约 1–2 个工作单元，之后每换一批素材都能立刻看到效果。

> 建议下一轮先做"阶段 0 + 玩家试点"，把管线和审美标准用最小的范围验证一遍，再批量铺开。
