# 美术 v2 制作合同（侧视近战方向）

> 配套文档：[ART-V2.md](ART-V2.md) 是**分阶段路线图**；本文是**逐个资产的制作与验收合同**。
> 方向依据：[GAMEPLAY-DIRECTION.md](GAMEPLAY-DIRECTION.md)——主体验是侧视小镇探索 + 近战连击、
> 体力、闪避与格挡，不是俯视双摇杆射击。
>
> **1.1.1 起作废的旧条目**：四向角色、8 向持械、枪口锚点、640×360 虚拟画布、四射击职业体态、
> 132 帧/角色的射击动作集。这些来自已被否决的 1.1.0 射击样板，保留在 Git 历史中供参考。

## 现状

角色、敌人、建筑、地面目前全部由 `web/src/renderer.js` 用 `fillRect` / `poly` 程序绘制，
逻辑分辨率 960×540。**以下资产均尚未制作**——本文件是接口合同，不是可直接导入的完成图集。
分阶段替换顺序见 [ART-V2.md](ART-V2.md)。

## 基准与锚点

| 项 | 约定 |
| --- | --- |
| 逻辑画布 | 960×540（`renderer.w/h`），像素风只允许整数倍缩放 |
| 角色尺寸 | 约 56 px 高（`human()` 当前绘制 y-58 到 y+2），**脚底为逻辑锚点** |
| 朝向 | 只有左/右两种，允许整图镜像 |
| 不对称配件 | 格伦的金属支具、洛恩的军用斗篷、米洛的护目镜、巡界者的腰间提灯——**镜像会翻转这些细节**，需要单独一帧或在镜像后修正 |
| 受击判定 | 由 `hitPlayer` 的距离判定决定，与精灵无关：**换图不得改变命中半径** |
| 攻击判定 | 「生效时点 + 前方矩形」：命中点在 `COMBO[i].impact`，前方 115 / 纵深 ±76。**不由精灵边缘决定攻击范围** |
| 遮罩 | 角色、敌人、特效各自独立层，避免被背景吞没 |

## 导出合同

- 逐像素无损源文件 + 透明 PNG 图集 + atlas JSON + 逐帧时长（毫秒）+ 脚/手/武器锚点 + 遮挡顺序。
- **游戏精灵不使用有损 WebP**；只有大幅背景板可以用 WebP（现有 `title.webp` / `world.webp` 即此例）。
- atlas 建议字段：`assetId`、`facing`、`action`、`frames[{rect,durationMs,foot,hand,weapon,layer}]`、`paletteId`、`sourceFile`、`status`。
  **这是待制作的接口合同，运行时尚未接入图集加载**——接入工作在 ART-V2.md 阶段 0。
- 图集每帧挤出 2 像素；运行时禁用平滑（`imageSmoothingEnabled=false` 已生效）。
- **逻辑伤害、无敌帧、格挡窗口独立于动画帧**，不允许用更快的动画偷偷改变攻速或移速。

## 色板与光照

- 全套素材收敛到 32–48 色受限色板，落地为 `web/assets/palette.json`；代码里不再出现裸色值。
- 约定光从右上、色温偏暖；所有阴影统一偏冷、方向一致。
- 角色边缘加 1 px 亮边或暗边，保证在浅色墙面（如旅店外墙 `#887b6a`）前仍然可读——
  这是当前程序方块最明显的问题。
